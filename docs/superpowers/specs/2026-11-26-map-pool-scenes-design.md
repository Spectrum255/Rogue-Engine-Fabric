# 随机地图集与固定场景设计

## 目标

为 Rogue Engine Fabric 增加数据包驱动的随机地图集。每个箱庭创建时从声明范围内确定性抽取一个固定场景，之后重入保持该地图；模板声明的刷新策略可以恢复场景初始状态，从而支持固定场景反复挑战。

## 非目标

本阶段不实现以下内容：

- Mod Menu 图形配置界面。
- 玩法任务、完成条件或奖励系统。
- 多人跨箱庭匹配。
- 客户端直写专用服务器文件。

图形配置、ZIP 导出和地图预览作为后续客户端工具阶段实现。

## 核心语义

- 地图集条目支持原版结构 `.nbt` 和模组固定场景快照。
- 每个箱庭只在创建时抽取一次。
- 创建模板和创建命令都可以声明抽取范围，最终范围为两者交集。
- 刷新不重新抽取地图，只恢复当前选中地图的初始状态。
- 普通重入保留当前探索状态。
- 销毁并重新创建箱庭时重新抽取。

## 数据模型

### `map_scene` 动态注册表

路径：

```text
data/<pack_namespace>/rogue-engine-fabric/map_scene/<scene_id>.json
```

场景定义包含：

- `schema_version`。
- `source`：`structure` 或 `snapshot`。
- 来源 ID 或相对路径。
- 场景边界、锚点和出生点。
- 旋转、镜像和结构处理器配置。
- 默认刷新策略。
- 内容哈希与校验信息。

### `map_pool` 动态注册表

路径：

```text
data/<pack_namespace>/rogue-engine-fabric/map_pool/<pool_id>.json
```

地图集定义包含：

- `schema_version`。
- 加权场景条目列表。
- 默认抽取范围，可按标签、场景 ID 或显式条目列表过滤。
- 重复策略：允许重复或按世界范围循环不重复抽取。
- 基础地形与维度类型。
- 刷新触发与玩家状态重置策略。
- 尺寸、实体数量和粘贴性能预算。

### Profile 模板

新增 `generator_kind=map_pool`。模板引用地图集，并可声明默认抽取范围。Profile 创建时可通过命令参数进一步限定范围。

### 箱庭场景快照

创建时生成实例级描述，包含：

- 地图集 ID 与内容哈希。
- 选中场景 ID 与内容哈希。
- 抽取 seed、权重和循环进度。
- 旋转、镜像、放置原点与出生点。
- 刷新策略。
- 场景缓存相对路径。
- 刷新次数与玩家状态快照引用。

选中的结构或场景文件复制到箱庭专属缓存。已有箱庭之后不再依赖原地图集文件。

## 创建流程

1. 解析 Profile 和 `map_pool` 模板。
2. 合并模板范围与创建时筛选条件。
3. 根据地图集哈希、创建 seed 和权重确定性抽取场景。
4. 校验边界、出生点、尺寸、实体数量和性能预算。
5. 将来源复制到箱庭缓存并计算哈希。
6. 写入 catalog 定义与 WAL 创建意图。
7. 创建基础维度。
8. 在服务器线程分批粘贴结构或场景快照。
9. 验证出生点安全后提交 `ACTIVE`。

任一步失败都不保留活动维度，沿用现有 `RECOVERY_REQUIRED` 恢复路径。

## 结构放置

- 结构来源使用原版 `StructureTemplateManager` 加载。
- 放置支持旋转、镜像和模板声明的处理器。
- 结构边界必须完全位于地图可玩区域和原版硬世界边界内。
- 结构中的方块实体按原版语义恢复；非玩家实体是否导入由模板策略决定。

## 场景快照

场景快照是模组管理的只读源副本，包含：

- JSON 元数据。
- 区块或区域块数据。
- 方块实体 NBT。
- 可选非玩家实体 NBT。
- 内容哈希和格式版本。

快照放置器按区块批量写入，受每 tick 时间和数量预算限制。目标区域先清理再粘贴，避免旧实体或方块实体残留。

## 刷新流程

新增 `RESETTING` 状态：

```text
ACTIVE -> RESETTING -> ACTIVE
ACTIVE -> RECOVERY_REQUIRED
RESETTING -> RECOVERY_REQUIRED
```

刷新步骤：

1. 校验实例状态、地图缓存和刷新策略。
2. 手动刷新和离开后触发要求维度内无玩家；死亡或完成事件只记录待刷新请求，等玩家被疏散或离开后再执行，避免在线探索时突然重建地图。
3. 写入 `COMPLETE_RESET` WAL 意图并提交 `RESETTING`。
4. 清理地图区域内的方块、实体和方块实体。
5. 从箱庭缓存重新粘贴当前选中地图。
6. 按模板策略生成玩家状态恢复快照；实际恢复发生在玩家下次进入该箱庭时。
7. 校验出生点后提交 `ACTIVE`。

支持的触发策略：

- 手动刷新。
- 最后一名玩家离开后刷新。
- 死亡后刷新。
- 预留玩法完成事件刷新接口，具体条件由后续玩法模块提供。

默认只重置地图世界，玩家状态沿用现有箱庭库存规则。

## 重入语义

- 重入不抽取新地图。
- 重入不自动刷新。
- 玩家看到上次离开时的地图状态。
- 刷新后恢复当前地图初始状态，但仍使用同一个地图条目。

## 完整存档与地图导入

支持输入：

- 原版结构 `.nbt`。
- 手动导入的地图文件或 ZIP。
- 完整 Minecraft 存档文件夹或 ZIP。

完整存档导入步骤：

1. 只读打开源存档。
2. 选择维度、中心点和包围盒，或扫描整个维度已生成区块。
3. 选择是否包含实体、容器、方块实体和结构引用。
4. 提取为统一场景快照。
5. 校验格式版本、尺寸、数量、引用和内容哈希。
6. 注册到 `map_scene` 或加入 `map_pool`。

导入不修改源存档。提取与注册分为两步，失败时不会留下半成品注册条目。

## 安全约束

- ZIP 导入拒绝路径穿越、符号链接和目录外写入。
- 限制解压总大小、文件数量、单个 NBT 大小、场景尺寸和实体数量。
- 场景缓存只能写入 `<world>/data/rogue-engine-fabric/scenes/<instance_uuid>/`。
- 销毁箱庭时场景缓存随维度库存进入隔离区。
- 专用服务器不开放客户端任意文件路径写入。

## 持久化与兼容性

- catalog 继续使用 schema 1，definition 增加可选场景快照字段。
- 旧箱庭缺少场景字段时按普通维度处理。
- WAL 新增 `COMPLETE_RESET`，崩溃后进入 `RESETTING` 的实例可重试清理和粘贴。
- 抽取历史与循环进度持久化，重启后不重复抽取当前地图。
- 已有世界不需要迁移。

## 性能约束

- 不在创建时同步预生成整个维度。
- 结构粘贴和场景快照粘贴按区块分批执行。
- 每 tick 限制操作时间、区块数、方块实体数和实体数。
- 不重复抽取只保存轻量循环进度，不保存全量历史。
- 超大场景必须在导入或创建前拒绝，而不是在运行期无限处理。

## 验证

### 单元测试

- 地图集 Codec 与范围校验。
- 加权确定性抽取。
- 标签/ID/显式列表筛选。
- 不重复循环与重启恢复。
- 结构旋转、镜像和边界校验。
- 场景快照序列化与内容哈希。
- `RESETTING` 状态机和 WAL 恢复。
- ZIP 路径穿越、大小和数量限制。
- 玩家状态重置策略。

### 服务端冒烟

- 创建随机地图箱庭。
- 重入保持选中地图。
- 手动刷新恢复初始场景。
- 离开后自动刷新。
- 归档/恢复后地图与刷新次数保持。
- 销毁后地图缓存进入隔离区。
